# 프라이데이 · LOCAL MATE

Ollama로 이 PC에서 실행하는 한국어 코딩·PC 작업·문서 작성 도우미입니다. 웹 앱은 Node.js 기본 모듈을 사용하며 외부 API 키가 필요하지 않습니다. 음성 및 문서 처리는 각각 분리된 프로젝트 전용 Python 환경을 사용합니다.

## 시작

1. Ollama를 실행합니다. 기본 연결 주소는 `http://127.0.0.1:11434`입니다.
2. 이 폴더의 `start-local-ai.cmd`를 더블 클릭합니다.
3. 브라우저에서 `http://127.0.0.1:3210`이 열립니다.

터미널에서는 `node server.mjs` 또는 `npm start`로 실행할 수 있습니다. Node.js 22 이상이 필요합니다. 종료는 실행 터미널에서 `Ctrl+C`를 누릅니다.

## 첫 작업

기본 작업 폴더는 앱 아래 `workspace`이며 `hello.js` 예제가 들어 있습니다. 다음 요청으로 실제 코드 작업을 확인할 수 있습니다.

> hello.js를 읽고 두 수를 곱하는 multiply 함수를 추가해 줘. 수정 후 node hello.js로 확인해 줘.

AI가 파일을 읽고 변경할 전체 내용을 제안합니다. **변경 적용**을 누르면 파일이 저장되고, 검증 명령은 **실행**을 눌러 진행합니다. 왼쪽 작업 폴더 이름을 누르면 기존 프로젝트의 전체 경로를 연결할 수 있습니다. 폴더를 바꾸면 대화가 초기화됩니다.

## 기능과 범위

- 한국어 대화, 코드 생성, 파일 목록·텍스트 읽기·검색
- 파일 변경 내용 검토와 적용, 저장 전 원본 백업
- 제안한 PowerShell 명령 검토와 실행, 출력·종료 코드 확인
- Windows 탐색기에서 작업 경로 열기, CPU·메모리 확인
- 설치된 모델 선택, 날씨 조회를 지원하는 대화 모드, 중지, 대화 텍스트 내보내기
- 마이크 음성 입력, 음성 파일 인식, 한국어 답변 읽기와 재생 중지

## 음성 대화

1. **프라이데이 자동 호출 대기**가 켜져 있으면 앱이 열릴 때 마이크 권한을 확인하고, 허용된 뒤에는 **프라이데이**라고 부르는 소리를 기다립니다. 권한 요청이 막히면 메시지 입력창 안의 **마이크 버튼**을 한 번 눌러 허용합니다.
2. **프라이데이, 오늘 할 일을 정리해 줘**처럼 이름을 앞에 불러 요청합니다. 약 1초 동안 조용해지면 자동으로 녹음을 끝내고 같은 입력창을 통해 전송하며, AI 답변을 음성으로 읽습니다.
3. 마이크 버튼을 한 번 누르면 사용자가 중지할 때까지 음성 대화 세션을 유지합니다. 답변 재생이 끝나면 바로 다시 듣기 시작합니다. **마이크 버튼을 다시 누르거나 종료를 누르면** 음성 입력과 연속 대화가 중지됩니다. 키보드 Escape로도 중지할 수 있습니다.

목소리·언어·자동 호출 대기·자동 전송·음성 답변·연속 대화 옵션은 상단 **프라이데이 설정 → 음성과 입력**으로 옮겼습니다. 전송 전에 내용을 고치려면 **인식 후 바로 전송**을 끕니다. 인식 결과는 기존 메시지 입력창에서 수정할 수 있습니다. **말 끝나면 자동 전송**을 끄면 입력창 안의 **음성 전송** 버튼으로 녹음을 마칠 수 있습니다. **음성 대화 답변 읽기**가 켜져 있으면 음성으로 보낸 요청의 다음 AI 답변을 읽습니다. 일반 텍스트 입력만 할 때는 마이크가 켜지지 않으며 답변을 자동으로 읽지 않습니다.

자동 호출 대기 중에는 이름으로 시작하지 않은 말은 전송하지 않고 다시 대기합니다. 이름만 부르면 “네, 말씀하세요.”라고 짧게 응답한 뒤 이후 요청을 이름 없이도 듣습니다. 이름과 첫 요청을 함께 말해도 이어서 대화할 수 있습니다. 한국어 기본 음성이 설치되어 있으면 호출 확인에는 빠른 기본 음성을 쓰고, 실제 AI 답변에는 설정한 목소리를 사용합니다. 마이크 버튼을 눌러 시작한 경우에도 이름만 부르면 같은 방식으로 응답합니다. 마이크 버튼을 누르면 **답변 후 계속 듣기**가 자동으로 켜져 사용자가 직접 중지할 때까지 듣기 세션을 유지합니다. 답변을 읽는 동안에는 녹음하지 않으며, 이전 답변의 **답변 듣기**를 눌러도 진행 중인 녹음을 먼저 중지합니다. **마이크 버튼을 다시 누르기**, 녹음 중 **취소**, **종료**는 마이크와 재생을 모두 중지합니다. 말소리 없이 15초가 지나면 해당 녹음을 버리고 다시 듣습니다. 시작한 대화에서는 잠시 조용히 있어도 이름을 다시 부를 필요가 없습니다. 모델 연결 문제로 전송하지 못하거나 음성 생성·재생에 실패하면 이유를 표시하고 세션을 종료해 마이크 버튼으로 다시 시작할 수 있게 합니다.

각 답변의 **답변 듣기**로 다시 들을 수 있습니다. 마이크 버튼과 답변 듣기를 누를 때 브라우저 음성 재생도 미리 준비합니다. 생성 중에는 입력창 안에 상태를 표시하며, 재생이 차단되거나 음성 생성에 실패하면 상태와 알림으로 원인을 표시합니다. 설정의 **음성 파일 불러오기**로 WAV·MP3·WebM·M4A 등의 파일도 인식할 수 있습니다. 한 번의 입력은 **60초·8MB 이하**입니다. 브라우저 마이크는 localhost에서 Chrome·Edge 사용을 권장합니다. 자동 호출 대기는 브라우저 마이크 권한이 필요하며, 브라우저 정책상 첫 음성 재생이 막히면 마이크 버튼이나 답변 듣기를 한 번 눌러 재생을 허용해야 할 수 있습니다. 자동 종료는 브라우저 오디오 분석 기능이 필요하며 소음과 마이크 감도에 따라 차이가 있습니다.

음성 인식은 `faster-whisper`의 **Whisper small / CPU int8**을 사용합니다. 답변 목소리는 **자연스러운 음성**과 **기본 음성 · 빠름** 중에서 고릅니다. 자연 음성이 설치되어 있으면 한국어 신경망 모델 **Qwen3-TTS 0.6B / Sohee**가 기본이며, NVIDIA GPU에서 이 PC 안에서 생성합니다. 기본 음성은 기존 Windows 한국어 목소리입니다. 선택은 브라우저에 기억됩니다. 자연 음성은 첫 준비와 생성에 시간이 필요하며, 짧게 나누어 다음 문장을 미리 생성합니다.

일반 대화의 녹음과 생성된 오디오는 메모리에서만 처리하고 별도 오디오 파일로 저장하지 않습니다. 음성 API로 외부 서버를 호출하거나 음성 사용료를 청구하지 않습니다. 코드 블록은 소리 내어 전부 읽지 않고 화면에서 확인하도록 안내합니다. 음성으로 요청해도 기존 파일 변경·명령 실행 검토는 동일하게 유지됩니다.

현재 PC에는 음성 인식 환경과 모델 설치가 완료되어 있습니다. 새 PC에서 설치하거나 설치를 복구할 때는 `setup-voice.cmd`를 실행합니다. Python 3.9 이상과 최초 설치용 인터넷이 필요하며, Whisper 모델은 약 500MB를 다운로드합니다. 설치 후 일반 음성 대화는 오프라인으로 동작합니다. Python 패키지와 모델은 `data/voice/`에 보관하고, 사용하지 않는 인식 모델은 약 2분 후 메모리에서 해제합니다. 프로젝트 위치를 옮긴 뒤 환경이 동작하지 않으면 새 위치에서 음성 설치를 다시 수행하세요.

자연 음성의 새 설치·복구는 음성 인식 설치 후 `setup-natural-voice.cmd`를 실행합니다. NVIDIA CUDA 실행 환경과 약 2.5GB의 음성 모델을 내려받으므로 최초 설치에는 인터넷과 수 GB의 추가 공간이 필요합니다. 인식용 Python 환경과 자연 음성용 환경은 분리됩니다. 사용하지 않는 자연 음성 모델도 약 2분 후 GPU 메모리에서 해제됩니다. 모델을 옮긴 뒤에는 새 위치에서 설치 명령을 다시 실행하세요. 목소리 복제는 사용하지 않습니다.

파일 도구는 연결한 작업 폴더 안에서 동작하고, 밖으로 향하는 링크와 `.env` 등의 인증 정보 파일을 제외합니다. **PowerShell은 별도 샌드박스가 아니며 일반 사용자 권한으로 PC 전체에 영향을 줄 수 있습니다.** 실행 전에 제안한 명령을 확인하세요. 화면 클릭 자동화, 관리자 작업, 지속 학습은 현재 포함되어 있지 않습니다.

## 이름과 호출 규칙

기본 이름은 **프라이데이**입니다. 상단 설정 버튼에서 이름과 **음성 대화를 시작할 때 이름 부르기**을 변경할 수 있습니다. 설정은 `data/assistant.json`에 저장되므로 새 대화, 작업 폴더 변경, 서버 재시작 후에도 유지됩니다. 모델을 다시 학습시키는 방식은 아닙니다. 이 규칙이 켜져 있으면 음성 대화를 시작할 때 이름을 먼저 부릅니다. 대화가 시작되면 종료할 때까지 후속 요청에서 이름을 생략할 수 있습니다. 이름만 말했을 때도 질문을 자동 생성하지 않습니다. 문서 버튼과 직접 입력한 텍스트 요청은 사용할 수 있습니다.

## 문서 작성

상단 **문서 만들기**에서 형식·제목·원하는 내용을 입력한 뒤 **AI에게 작성 요청**을 누릅니다. 로컬 모델이 본문을 완성해 저장 내용을 보여 주고, **문서 저장**을 누르면 실제 파일이 만들어집니다. 생성 결과의 **문서 내려받기**로 받을 수 있으며 파일은 연결한 작업 폴더에 저장됩니다. 음성으로 “프라이데이, 주간 업무 보고서를 워드 문서로 만들어 줘”라고 요청해도 같은 검토 절차를 사용합니다.

지원 형식은 **Word DOCX, Excel XLSX, PowerPoint PPTX, 한글 HWPX·HWP 5.0**입니다. 한컴 문서는 한컴 설치 없이 생성합니다. 한컴 프로그램 자체에서의 화면 호환성은 이 PC에 한컴 한글이 없어 확인하지 못했습니다. 한셀·한쇼에서는 Office 호환 형식인 XLSX·PPTX를 사용할 수 있습니다. Access·OneNote, 매크로, 구형 DOC·XLS·PPT와 모든 Office 기능을 구현한 것은 아닙니다.

**내용을 직접 작성해 저장하기**에서는 본문을 직접 입력해 저장할 수 있습니다. 제목(`#`), 목록(`-`), 표(`| 항목 | 값 |`)를 지원합니다. Word·한글은 문단과 표, Excel은 숫자·표와 SUM/AVERAGE·사칙연산 등의 제한된 수식, PowerPoint는 제목별 슬라이드와 표를 생성합니다. Excel 수식은 Excel에서 열 때 계산됩니다. 외부 연결 수식은 허용하지 않습니다. 파일 목록에서 기존 지원 문서를 누르면 텍스트·표를 미리 읽고 원본을 내려받을 수 있습니다. AI는 `read_document`로 읽고 새 파일로 재작성할 수 있습니다. 복잡한 기존 서식·개체를 그대로 유지하는 편집기는 아닙니다.

같은 이름의 파일은 덮어쓰지 않으므로 수정본은 새 이름으로 저장하세요. 읽기는 20MB 이하, 생성 본문은 60,000자 이하, 프레젠테이션은 60장 이하이며 긴 미리보기는 일부 생략됩니다. 새 PC에서는 `setup-documents.cmd`로 설치합니다. Python 3.10 이상과 최초 설치용 인터넷이 필요하며 설치 후 문서 생성·읽기는 오프라인으로 동작합니다.

앱은 `127.0.0.1`에만 바인딩하고 루프백 Ollama 주소만 사용합니다. 클라우드 모델 태그는 선택 목록에서 제외하며, 앱 자체의 외부 API 호출·분석 추적·외부 글꼴은 없습니다. 승인한 셸 명령이나 Ollama 자체 설정은 별개입니다.

## 모델

설치된 모델을 자동으로 표시하며 `qwen3.5:9b`를 기본으로 선택합니다. 이 앱은 공개 모델에 파일·명령 도구와 화면을 연결한 에이전트입니다. 앱 자체는 모델을 자동 다운로드하지 않습니다.

이 PC에서 확인한 구성은 RTX 5070 12GB, RAM 32GB, Node.js 24, Ollama입니다. 권장 모델은 `qwen3.5:9b`(약 6.6GB)입니다. 기존 `glm4`는 대화용으로 사용할 수 있지만 코딩 도구 선택이 부정확했습니다. `glm-4.7-flash`는 이 환경에서 `llama-server`의 CUDA 초기화 오류와 `0xc0000409` 종료가 확인되어 앱의 모델 선택 목록에서 제외합니다. 실제 응답 속도는 화면에 표시됩니다.

모델 응답은 JSON 스키마로 제한하고 서버에서 도구를 검증합니다. 최대 8회 작업 단계, 단계당 1개 도구를 실행하며 셸 명령은 60초로 제한됩니다. 긴 파일은 일부만 모델에 전달하며 전체를 읽지 못한 기존 파일은 수정하지 않습니다. 모델이 잘못된 코드를 제안할 수 있으므로 프로젝트에 맞는 테스트 결과를 확인하세요.

## 로컬 데이터

- `data/settings.json`: 선택한 작업 폴더와 모델
- `data/assistant.json`: 프라이데이 이름과 음성 호출 규칙
- `data/backups/`: 변경 전 파일 내용과 원래 경로
- `data/voice/`: 음성 인식·음성 생성 Python 환경과 모델
- `data/documents/`: 문서 처리 전용 Python 환경
- `data/voice-samples/`: 비교 검증 명령으로 만든 기존·새 목소리 WAV와 측정 결과
- 대화: 실행 중인 서버 메모리에만 보관. 필요한 대화는 우측 상단 내보내기로 저장

백업은 자동 삭제하지 않습니다. 원상 복구 시 해당 JSON의 `path`와 `before` 내용을 확인해 복원하세요. `before: null`은 새로 만든 파일을 뜻합니다. 백업에는 원본 코드가 포함될 수 있습니다.

2026-11-01 확인 결과: 자동 테스트 12개와 JavaScript 구문 검사가 통과했습니다. 실제 `qwen3.5:9b`로 예제 파일을 읽고 `subtract` 함수를 추가한 뒤 Node.js 실행 결과 `10 - 3 = 7`, 종료 코드 0을 확인했습니다. 모델은 RTX 5070 GPU에 전체 로드되었습니다. 첫 요청에는 모델 로딩 시간이 추가됩니다.

음성 기능 추가 후 자동 테스트 20개가 통과했습니다. Windows 한국어 음성으로 생성한 실제 WAV를 로컬 Whisper에서 인식해 한국어 원문과 일치하는 결과를 확인했습니다. 실제 음성 엔진 검증은 `node scripts/verify-voice.mjs`로 다시 수행할 수 있습니다. 이 검증 명령은 마이크를 사용하지 않고 테스트용 WAV를 `data/voice-check.wav`에 만듭니다.

자연 음성 비교는 `npm run compare:voices`로 수행합니다. 같은 한국어 문장을 기존 목소리와 새 목소리로 생성하고, 최초 준비 포함 시간·준비 후 생성 시간·오디오 길이를 `data/voice-samples/comparison.json`에 기록합니다. 새 목소리 WAV를 로컬 Whisper로 다시 인식해 발음을 확인합니다. 비교용 WAV는 해당 폴더에 저장됩니다.

자연 음성 업데이트에서는 자동 테스트 23개와 구문 검사를 통과했습니다. 이 PC의 비교 문장에서는 기존 목소리 생성 1.1초, 자연 음성 준비 후 생성 9.9초(오디오 6초)가 측정됐습니다. 새 환경의 첫 실행은 초기 준비를 포함해 83.2초였습니다. 실제 생성 파일을 로컬 음성 인식으로 확인한 문장은 원문과 일치했습니다. 자연 음성은 대기 시간이 더 길며, 빠른 응답이 필요하면 기본 음성을 선택할 수 있습니다.

입력창 통합 업데이트에서는 자동 테스트 34개와 구문 검사가 통과했습니다. 별도 음성 패널을 제거하고 같은 마이크 버튼으로 시작·종료하는 흐름, 같은 메시지 입력창에 인식 결과 넣기, 일반 텍스트 입력 시 마이크 비활성 유지, 답변 듣기, 마이크 권한 대기 중 취소를 확인했습니다.

위치를 자동 추적하지 않습니다. 일부 동·읍 이름을 찾지 못하면 가까운 시·군을 사용하세요.

실제 관측소 측정값과 차이가 날 수 있습니다. 오늘·내일은 조회 지역의 현지 날짜 기준입니다.

### 호출어와 자연 음성 응답 개선

- 기본 이름 ‘프라이데이’는 띄어쓰기와 제한된 인식 변형(후라이데이, 프라이데, Friday)을 허용합니다. 사용자 지정 이름에는 기본 이름의 별칭을 적용하지 않습니다. 호출을 놓치면 상태 표시줄에 인식한 문구가 표시됩니다.
- 음성 인식기에 설정된 이름을 힌트로 전달하며, 자동 호출 대기에서는 작은 소리 감지 기준을 낮춥니다. 마이크와 주변 소음에 따라 실제 인식률 확인이 필요합니다.
- 자연 음성은 첫 구간을 최대 48자로 생성하고 이후 구간은 기존 최대 160자로 처리합니다. 첫 재생까지 기다리는 분량을 줄이며 전체 합성 속도의 향상을 보장하지는 않습니다.
- 음성 대화가 켜져 있고 자연 음성 및 자동 읽기를 선택했을 때 60초마다 준비 상태를 갱신합니다. 대화 종료 후에는 기존 2분 유휴 해제 정책을 따릅니다. 대화 중에는 음성 모델의 GPU 메모리 사용이 유지됩니다. 브라우저가 백그라운드 타이머를 제한하면 모델이 해제될 수 있습니다.

PC 확인: `codex/voice-responsiveness` 브랜치를 받아 서버를 재시작하고 페이지를 새로 고칩니다. ‘프라이데이’, ‘후라이데이, 수원 날씨 알려줘’를 말해 호출과 명령을 확인합니다. 자연 음성으로 긴 답변을 듣고 첫 재생 시간을 비교하며, 3분 후 다시 질문하고 대화 종료 버튼도 확인합니다. 실제 마이크 인식과 GPU 속도는 Windows PC에서 검증해야 합니다.
